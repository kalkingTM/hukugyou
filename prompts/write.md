# 執筆の手順

## 調査
- WebSearch で、その検索語の上位記事が「何を書いていて、何が足りないか」を確認する（文章は真似しない）。
- 使う関数・機能の仕様と対応バージョンを Microsoft 公式サポート（support.microsoft.com）で確認する。
- 制度が絡む話（経費・勘定科目・労働時間など）は一次情報を確認し、一般論にとどめる。

## 記事の構成（この順で書く）
1. **結論**（2〜3行）: 何ができるようになるか。使う数式を1行で。
2. **完成形の表**: 見本ファイルと同じ内容のMarkdown表（5〜10行）。
3. **作り方**: 手順を番号付きで。各数式はコードブロックで、入れるセルを明記。数式の意味を部品ごとに説明。
4. **つまずきやすい点**: エラーになる典型例と直し方（2〜4個）。
5. **応用**: 条件を変えたいときの書き換え例（1〜2個）。
6. **見本ファイル**: 記事上部のダウンロード欄に自動表示されるので、本文では「見本ファイルで動きを確認できます」と触れるだけ。
7. （`affiliates.json` に関係する案件がある場合のみ）**さらに学ぶなら**: 1〜2個、なぜ役立つかを1文添えて。

- 分量の目安: 2,000〜4,000字。水増ししない。
- 見出しは `##` と `###` のみ。
- バージョン差がある関数は、古いExcelでの代わりの数式も書く。

## 検索とAI回答に引用されやすい書き方（SEO・AIO）
検索結果やAIの回答は、「質問に直接答えている、短くて独立した文」を引用する。次を守る。

- **冒頭の「結論」は、それだけ読めば答えになる2〜3文にする。** 「この記事では〜を解説します」ではなく、答えそのもの（使う数式と結果）を先に書く。前置きや自己紹介は書かない。
- **題名（title）は、検索語の言い回しを先頭に置く。** 例: 「Excelで土日祝を除いた営業日数を数える方法｜NETWORKDAYS関数」。32字前後。
- **説明（description）は80〜120字。** 検索語と、読者が得られる結果を入れる。
- **見出し（##）は、読者のやりたいこと・疑問の言葉にする。** 例: 「祝日に色が付かないときは」。「まとめ」「はじめに」のような中身のない見出しは使わない。
- **1つの段落は1つの主張。** 数式の説明は「この部分は〜を返します」と、1文で言い切る。
- **用語は初出で定義する。** 例: 「シリアル値（Excelが日付を管理している数字）」。
- **よくある質問を2〜3個、末尾の前に入れる**（見出し「よくある質問」の下に、`### 質問文` と、1〜3文の直接の答え）。実際に読者が検索しそうな質問だけを選ぶ。水増しの質問は入れない。
- **内部リンク: 関連する既存記事があれば、本文中に1〜3本リンクする**（`/hukugyou/posts/<slug>/` の形式。既存記事の slug は `src/content/posts/` のファイル名）。無理に入れない。
- 表は見出し行を付ける。数値や結果は、記事内で何度も同じ値を使い回して食い違わせない。
- 画像は使わない（代わりに表とコードブロックで示す）。

- 本文で「税理士として」「税理士が監修」「私の経験では」など、運営者の肩書きや個人の経験を書かない（運営者情報は記事末尾に自動で出る）。
